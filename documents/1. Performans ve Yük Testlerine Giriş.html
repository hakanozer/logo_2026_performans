1) Performans Testi ve Yük Testi Nedir?

Performans testi, bir uygulamanın belirli bir iş yükü altında ne kadar hızlı, stabil ve ölçeklenebilir çalıştığını ölçer. Yük testi ise bu performans testinin en yaygın türüdür ve sisteme beklenen gerçek kullanıcı yükü verilerek davranış gözlemlenir.

Örnek: ERP sipariş modülünde 200 eşzamanlı kullanıcı ile sipariş kaydetme işlemi yapılırken yanıt süreleri ve hata oranı ölçülür.

Neden Önemli?
Canlıya geçmeden önce kapasite sınırlarını görmek, sonradan yaşanacak kesinti ve memnuniyetsizliği azaltır.
Dikkat / Sık Yapılan Hata
Sadece ortalama süreye bakmak yanıltır. Kuyrukta bekleyen az sayıdaki çok yavaş istek, kullanıcı deneyimini ciddi bozabilir.

2) Stress, Spike ve Soak Test Kavramları

  • Stress Test: Sistem sınırın ötesine zorlanır. Amaç kırılma noktasını bulmaktır.
  • Spike Test: Yük çok kısa sürede ani artırılır. Amaç ani kampanya/duyuru etkisini görmek.
  • Soak Test: Uzun süreli sabit yükte sistemin yıpranması gözlenir.

Middleware örneği: Gece entegrasyon penceresinde 6 saat boyunca sabit mesaj akışında bellek sızıntısı var mı, soak test ile anlaşılır.

Neden Önemli?
Her test türü farklı riski ortaya çıkarır; sadece load test yapmak üretim risklerini tam kapsamaz.
Dikkat / Sık Yapılan Hata
Spike testi yapmadan kampanya gününe çıkmak, ani yükte bağlantı havuzu tükenmelerine yol açabilir.

3) Performans Testi ve Fonksiyonel Test Farkı

Fonksiyonel test, "doğru sonuç geldi mi" sorusunu yanıtlar. Performans testi ise "doğru sonuç ne kadar sürede, kaç kullanıcıyla ve ne kadar stabil geliyor" sorusuna odaklanır.

Fonksiyonel testte 1 kullanıcı ile başarılı olan işlem, 300 kullanıcıda 12 saniyeye çıkabilir. Bu durumda fonksiyonel olarak doğru, performans olarak başarısızdır.

Neden Önemli?
Kurumsal sistemlerde gecikme, fonksiyonel hatadan bağımsız şekilde iş kaybı yaratabilir.
Dikkat / Sık Yapılan Hata
Sadece "hata yok" demek yetmez; SLA hedefleri karşılanmıyorsa canlı sistemde kullanıcı şikayeti kaçınılmazdır.

4) Performans Testlerinde Test Uzmanının Rolü

Kod yazmadan da büyük değer üretebilirsiniz: doğru senaryo seçimi, doğru metrik takibi, doğru yorumlama. Test uzmanı iş akışını anlar, hangi adımın kritik olduğunu belirler ve gerçek kullanıcı davranışını araca taşır.

Örnek katkı: ERP finans modülünde ay sonu kapanış işleminin, normal güne kıyasla farklı yük profili taşıdığını tespit edip ayrı test senaryosu tanımlamak.

Neden Önemli?
Doğru kurgulanmış senaryo, geliştirici ve altyapı ekiplerine doğrudan aksiyon aldıran somut veri üretir.
Dikkat / Sık Yapılan Hata
Sadece araç ekranına odaklanıp iş süreç bağlamını kaçırmak, testin temsil gücünü düşürür.

5) Test Edilecek Uygulama ve Modüllerin Belirlenmesi

Önceliklendirme kuralı: yüksek işlem hacmi + iş açısından kritik + pik saatte yoğun kullanılan modüller önce test edilir.

  1. İş birimleriyle görüşün: "Hangi ekran/işlem yavaş olursa iş durur?"
  2. Geçmiş olay kayıtlarına bakın: sık timeout veren endpoint veya ekranları toplayın.
  3. Modül bazlı yük profili çıkarın: stok, finans, satınalma, entegrasyon gibi.
Neden Önemli?
Kaynağı en çok etkileyen işlemlere odaklanmak test maliyetini düşürür, etkiyi artırır.
Dikkat / Sık Yapılan Hata
Az kullanılan bir ekranı uzun test edip kritik API'yi test dışı bırakmak yanlış kapasite kararı doğurur.

6) Test Ortamının Belirlenmesi

Test ortamı üretime ne kadar benzerse sonuçların güvenilirliği o kadar artar. Donanım boyutu, veritabanı sürümü, ağ gecikmesi ve entegrasyon bağımlılıkları kayıt altına alınmalıdır.

ERP/middleware tarafında özellikle kuyruk yöneticisi, API gateway, kimlik doğrulama servisi gibi katmanların dahil edilip edilmediği netleştirilmelidir.

Neden Önemli?
Gerçek dışı küçük ortamda iyi görünen sonuçlar, canlıda çökme riski yaratır.
Dikkat / Sık Yapılan Hata
Paylaşımlı test ortamında başka ekiplerin yükü ölçümü kirletir; test penceresi izolasyonu planlanmalıdır.

7) Test Senaryolarının Oluşturulması

Senaryo, kullanıcının gerçek iş adımlarının sırasıdır. Sadece login çağrısı yapmak yerine "giriş → arama → kayıt açma → onaylama → rapor görüntüleme" gibi uçtan uca akışlar kurulmalıdır.

  1. Kritik iş akışını süreç sahiplerinden doğrulayın.
  2. Her akış için beklenen kullanıcı oranını belirleyin (ör. %40 sorgu, %35 kayıt, %25 rapor).
  3. Test verilerini gerçekçi dağıtın (farklı müşteri, tarih, ürün, depo vb.).
Neden Önemli?
Gerçek davranışa yakın model, darboğazın doğru katmanda görünmesini sağlar.
Dikkat / Sık Yapılan Hata
Tek endpoint'i aşırı döndürmek, gerçek hayatta hiç görülmeyen yapay hotspot üretir.

8) Kullanıcı Sayısı, Test Süresi ve Başarı Kriterleri

Başarı kriterleri test başlamadan yazılı olmalıdır. Örnek kriter: 300 eşzamanlı kullanıcıda 95. persentil yanıt süresi 2.5 saniyeyi aşmayacak, hata oranı %1 altında kalacak.

Test süresi kısa tutulursa ısınma etkisi, bağlantı havuzu davranışı, uzun süreli bellek tüketimi gibi etkiler kaçabilir.

Neden Önemli?
Önceden tanımlı kriter, sonuç yorumunu tartışmadan ölçülebilir hale getirir.
Dikkat / Sık Yapılan Hata
"Bakalım ne çıkacak" yaklaşımı test sonunda ortak karar almayı zorlaştırır.

9) UI ve API Testlerinin Ayrıştırılması

UI testleri kullanıcı deneyimini, tarayıcı etkisini ve ön yüz render maliyetini içerir. API testleri backend kapasitesini daha net ölçer. ERP'de çoğu kapasite kararı API seviyesinden çıkar; UI testleri doğrulama amacıyla daha az oranda eklenir.

Örnek karar: Satınalma ekranı yavaşsa önce aynı işlemin API çağrısı test edilir. API hızlı ama ekran yavaşsa sorun UI katmanında aranır.

Neden Önemli?
Doğru katmanda test yapmak, ekiplerin aksiyon süresini ciddi kısaltır.
Dikkat / Sık Yapılan Hata
Tüm testleri sadece UI'dan yürütmek; kök nedeni backend/UI ayrımında bulanıklaştırır.

10) Uygulama/Teknoloji Tiplerinin Tanınması

  • Web Uygulaması: Tarayıcı + API + veritabanı zinciri.
  • REST API: Mobil, web ve diğer sistemlerin çağırdığı servis katmanı.
  • Mobil + Backend: Mobil istemci farklı ağ koşullarına sahip olduğundan API stabilitesi kritik.
  • ERP Uygulamaları: Modül bazlı farklı işlem ağırlıkları (finans CPU, raporlama I/O vb.).
  • Middleware: Kuyruk, dönüşüm, yönlendirme; gecikme zincirleme etkiler yaratır.
  • Masaüstü Uygulamalar: Uygulama içinden dışa açık sandbox API'ler üzerinden performans ölçümü yapılabilir.
Neden Önemli?
Teknoloji tipini bilmek doğru ölçüm noktasını seçtirir.
Dikkat / Sık Yapılan Hata
Masaüstü uygulamayı yalnızca ekran etkileşimiyle test etmek, backend darboğazını görünmez bırakır.

11) Java/.NET/Node.js/Python Tabanlı Sistemlerde Yaklaşım Farkı

Java: Heap yönetimi ve GC davranışı izlenir. Uzun testlerde bellek paterni önemlidir.

.NET: Thread pool ve GC basıncı takip edilir. Ani yükte kuyruk büyümesi gözlenebilir.

Node.js: Olay döngüsü tek iş parçacığı yapısından dolayı bloklayıcı işlemlere duyarlıdır.

Python: Çalışma modeli ve servis mimarisi (senkron/asenkron) throughput sınırını etkileyebilir.

Neden Önemli?
Kod yazmasanız da teknolojiye göre hangi metriğe bakacağınızı bilmek yorum kalitesini yükseltir.
Dikkat / Sık Yapılan Hata
Her teknolojiye aynı eşiklerle yaklaşmak, yanlış karşılaştırmalara neden olur.

12) Kısa Öz Değerlendirme / Düşündürme Soruları

  1. Çalıştığınız sistemde en kritik 3 işlem hangileri ve neden?
  2. Yoğun saatlerde hangi modülün daha fazla kaynak tükettiğini biliyor musunuz?
  3. API ve UI tarafında ayrı başarı kriteriniz var mı?
  4. Hangi metrikte alarm üretildiğinde iş etkisi en yüksek olur?
  5. Son 6 ayda yaşanan performans olaylarının ortak deseni neydi?
Neden Önemli?
Teknoloji yığınınızı ve risk noktalarınızı netleştirmek, sonraki modüllerdeki örnekleri kendi ortamınıza uyarlamanızı kolaylaştırır.
Dikkat / Sık Yapılan Hata
"Bizde sorun yok" varsayımıyla ilerlemek, test kapsamını gereğinden dar tutar.

13) Araç Kurulumları (Windows / macOS / Linux)

Tüm kurulumlarda ilke aynı: indir, kur, sürüm doğrula, eğitimdeki kullanım amacını netleştir.

13.1 Java JDK

İndirme: https://www.oracle.com/java/technologies/downloads/

JMeter Java olmadan çalışmaz. Bu nedenle önce JDK kurulur, sonra JAVA_HOME ayarlanır.

Windows

  1. Oracle sitesinden Windows x64 installer dosyasını indirin.
  2. Kurulum sihirbazında varsayılan adımlarla devam edin.
  3. Denetim Masası → Sistem → Gelişmiş sistem ayarları → Ortam Değişkenleri.
  4. Yeni sistem değişkeni: Ad = JAVA_HOME, Değer = JDK klasör yolu.
  5. Path içine %JAVA_HOME%\bin ekleyin.

macOS

  1. Oracle pkg dosyasını indirip kurun.
  2. Terminalde kabuk dosyasına JAVA_HOME ekleyin (zsh için .zshrc).
echo 'export JAVA_HOME=$(/usr/libexec/java_home)' >> ~/.zshrc
echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

Linux (Ubuntu örneği)

  1. JDK paketini kurun.
  2. JAVA_HOME değişkenini profile ekleyin.
sudo apt update
sudo apt install -y openjdk-17-jdk
echo 'export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64' >> ~/.bashrc
echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
java -version

Beklenen: sürüm bilgisi görünmeli. "command not found" görüyorsanız PATH/JAVA_HOME kontrol edilmelidir.

13.2 Apache JMeter

İndirme: https://jmeter.apache.org/download_jmeter.cgi

  1. Binary zip/tgz paketini indirin ve bir klasöre açın.
  2. JMeter başlatın: Windows'ta jmeter.bat, macOS/Linux'ta jmeter scripti.
# macOS/Linux
cd /opt/apache-jmeter-5.6.3/bin
./jmeter

Arayüz açıldığında kurulum tamamdır. Eğitimde senaryo hazırlama, yürütme ve raporlama için ana araçtır.

13.3 JMeter Plugins Manager

İndirme: https://jmeter-plugins.org/install/Install/

  1. sitesinden verilen PluginsManager.jar dosyasını indirin.
  2. Dosyayı JMeter klasöründe lib/ext içine kopyalayın.
  3. JMeter açıksa kapatıp yeniden başlatın.
  4. JMeter üst menüde Options → Plugins Manager görünmelidir.
Neden Önemli?
Ek listener ve gelişmiş bileşenleri güvenli şekilde yüklemenizi sağlar.
Dikkat / Sık Yapılan Hata
Jar dosyasını yanlış klasöre koymak veya JMeter'ı yeniden başlatmamak menünün görünmemesine neden olur.

13.4 Postman

İndirme: https://www.postman.com/downloads/

Kurulumdan sonra API çağrılarını doğrular, ardından JMeter'a taşırsınız.

  1. Postman'i açın → New → HTTP Request.
  2. Method ve URL girin, gerekirse Authorization sekmesinden token tanımlayın.
  3. İstek başarılıysa Code butonundan cURL formatında export edin.

13.5 Git

İndirme: https://git-scm.com/downloads

Bu eğitimde amaç kod geliştirme değil, JMeter .jmx dosyalarını ve test raporlarını ekip içinde versiyonlu paylaşmaktır.

git clone https://ornek-sirket/perf-test-repo.git
cd perf-test-repo
git add .
git commit -m "Yeni yük testi senaryosu ve sonuçlar"
git push

Yorum: clone ile depo alınır, add ile dosyalar hazırlanır, commit değişiklik kaydıdır, push merkezi depoya gönderir.

13.6 Docker Desktop

İndirme: https://www.docker.com/products/docker-desktop/

InfluxDB ve Grafana'yı lokal ortamda hızlı ayağa kaldırmak için kullanılır.

docker --version
docker compose version

Doğrulama sonrası proje klasöründe docker-compose dosyası oluşturun:

version: "3.8"
services:
  influxdb:
    image: influxdb:1.8
    container_name: influxdb
    ports:
      - "8086:8086"
    environment:
      - INFLUXDB_DB=jmeter
  grafana:
    image: grafana/grafana:10.4.2
    container_name: grafana
    ports:
      - "3000:3000"
    depends_on:
      - influxdb
docker compose up -d
docker ps

Tarayıcı erişimi: Grafana için http://localhost:3000, InfluxDB API için http://localhost:8086

13.7 InfluxDB

İndirme: https://www.influxdata.com/downloads/

Performans metriklerini zaman serisi olarak saklar. JMeter verileri burada tutulur.

curl -I http://localhost:8086/ping

13.8 Grafana

İndirme: https://grafana.com/grafana/download/

Kurulum sonrası ilk girişte admin hesabı oluşturun. Ardından data source tanımlayın:

  1. Sol menüden Connections → Data sources → Add data source.
  2. InfluxDB seçin.
  3. URL alanına http://influxdb:8086 (Docker ağı) veya http://localhost:8086 yazın.
  4. Database alanına jmeter girin.
  5. Save & Test ile doğrulayın.

13.9 Dynatrace

Bilgi ve erişim: https://www.dynatrace.com/

OneAgent kurulumu çoğu kurumda altyapı/geliştirici ekip koordinasyonu gerektirir.

  1. Dynatrace tenant'a giriş yapın.
  2. Deploy Dynatrace bölümünden hedef OS'e uygun OneAgent komutunu alın.
  3. Sunucuda komutu çalıştırın, servis yeniden başlatma gereksinimini teyit edin.
  4. Dynatrace arayüzünde host ve process görünürlüğünü doğrulayın.
Neden Koordinasyon Gerekir?
Ajan kurulumu güvenlik politikaları, değişiklik yönetimi ve bakım penceresi gerektirebilir.

13.10 JMeter GUI ve Non-GUI Mod Farkı

Senaryo hazırlığı GUI ile kolaydır; gerçek yük koşumu ise non-GUI modda yapılmalıdır. Çünkü GUI render maliyeti JMeter'ın kendi kaynak tüketimini artırır, sonuçları çarpıtabilir.

jmeter -n -t test.jmx -l sonuc.jtl

Açıklama: -n non-GUI, -t test planı dosyası, -l sonuç dosyasıdır.

13.11 Postman'dan cURL alıp JMeter'a taşıma akışı

  1. Postman'da doğrulanmış istekte Code seçin, cURL kopyalayın.
  2. JMeter'da Thread Group altında Add → Sampler → HTTP Request.
  3. cURL içindeki URL, method, header, body bilgilerini ilgili alanlara aktarın.
  4. View Results Tree ile response code ve body kontrol edin.

13.12 Her Araç İçin İşletim Sistemi Bazlı Uygulama Özeti

Bu bölümde listedeki her araç için Windows, macOS ve Linux adımlarını tek yerde karşılaştırmalı görebilirsiniz. Amaç, katılımcının kendi işletim sisteminde adım kaçırmadan ilerlemesidir.

Apache JMeter

Windows
  1. Zip paketini indirin ve örneğin C:\tools\apache-jmeter klasörüne açın.
  2. bin klasöründeki jmeter.bat dosyasını çift tıklayın.
  3. Arayüz açılıyorsa kurulum tamamdır.
macOS
  1. tgz paketini indirip bir klasöre açın.
  2. Terminal ile bin klasörüne geçip jmeter scriptini çalıştırın.
cd ~/tools/apache-jmeter-5.6.3/bin
  ./jmeter
Linux
  1. tgz paketini açın ve çalıştırma izni verin.
  2. bin/jmeter scriptini çalıştırın.
cd ~/tools/apache-jmeter-5.6.3/bin
  chmod +x jmeter
  ./jmeter

JMeter Plugins Manager

Windows
  1. PluginsManager.jar dosyasını indirin.
  2. Dosyayı JMeter\lib\ext klasörüne kopyalayın.
  3. JMeter'ı kapatıp yeniden açın.
macOS
  1. Jar dosyasını indirin.
  2. apache-jmeter/lib/ext klasörüne kopyalayın.
  3. Uygulamayı yeniden başlatın.
Linux
  1. Jar dosyasını indirin.
  2. lib/ext içine yerleştirin ve JMeter'ı yeniden başlatın.

Postman

Windows
  1. Installer (.exe) dosyasını indirip çalıştırın.
  2. Kurulum sonrası Start menüsünden Postman'i açın.
macOS
  1. .zip/.dmg paketini indirip Applications klasörüne taşıyın.
  2. Launchpad üzerinden Postman'i başlatın.
Linux
  1. Tar.gz veya snap paketiyle kurulum yapın.
  2. Uygulama menüsünden Postman'i başlatın.
sudo snap install postman

Git

Windows
  1. Git for Windows installer'ını kurun.
  2. Git Bash açıp sürümü doğrulayın.
git --version
macOS
  1. git-scm paketini veya Xcode Command Line Tools kurulumunu tamamlayın.
  2. Terminalden sürümü kontrol edin.
git --version
Linux
  1. Paket yöneticisiyle Git kurun.
  2. Sürüm doğrulaması yapın.
sudo apt install -y git
  git --version

Docker Desktop / Docker Engine

Windows
  1. Docker Desktop installer'ı çalıştırın.
  2. WSL2 entegrasyon ayarını etkinleştirin.
  3. Docker Desktop açıldığında sürüm doğrulayın.
docker --version
  docker compose version
macOS
  1. Apple Silicon/Intel sürümüne uygun Docker Desktop indirip kurun.
  2. Uygulamayı başlatın ve terminal doğrulaması yapın.
docker --version
  docker compose version
Linux
  1. Docker Engine ve Docker Compose plugin kurun.
  2. Kullanıcı yetkisini ayarlayıp servisi başlatın.
sudo apt install -y docker.io docker-compose-plugin
  sudo systemctl enable --now docker
  docker --version
  docker compose version

InfluxDB

Windows
  1. MSI paketini veya Docker yöntemini seçin.
  2. Servis başlatıldıktan sonra ping endpoint'i kontrol edin.
curl -I http://localhost:8086/ping
macOS
  1. Homebrew veya Docker ile kurun.
  2. Port 8086 erişimini doğrulayın.
curl -I http://localhost:8086/ping
Linux
  1. Resmi depodan paketi kurun veya Docker ile ayağa kaldırın.
  2. Servis durumunu ve ping yanıtını doğrulayın.
curl -I http://localhost:8086/ping

Grafana

Windows
  1. MSI installer ile kurun, service olarak başlatın.
  2. Tarayıcıdan localhost:3000 açın.
macOS
  1. Homebrew veya Docker yöntemiyle kurun.
  2. localhost:3000 üzerinden giriş yapın.
Linux
  1. Grafana paketini kurup servisi başlatın.
  2. Tarayıcıdan 3000 portunu doğrulayın.
sudo systemctl enable --now grafana-server

Dynatrace OneAgent

Windows
  1. Dynatrace tenant'tan Windows OneAgent installer indirin.
  2. Yönetici yetkisiyle çalıştırın, hedef host tag bilgisi girin.
  3. Host görünürlüğünü Dynatrace arayüzünde doğrulayın.
macOS
  1. macOS kurulum paketini tenant'tan alın.
  2. Kurulum komutunu terminalde çalıştırın.
  3. Dynatrace içinde process görünürlüğünü kontrol edin.
Linux
  1. Tenant'ın verdiği shell komutunu sunucuda çalıştırın.
  2. Kurulum sonrası servis/agent durumunu doğrulayın.
  3. Güvenlik ve değişiklik yönetimi onaylarını kayıt altına alın.
Neden Önemli?
Her aracın işletim sistemine göre küçük farkları vardır; bu farklar adım atlamayı ve yanlış kurulum riskini azaltmak için net yazılmalıdır.
