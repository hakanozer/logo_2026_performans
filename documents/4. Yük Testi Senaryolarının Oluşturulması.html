Modül 4: Yük Testi Senaryolarının Oluşturulması

Bu modülde gerçek kullanıcı davranışını sanal kullanıcı modeline çevirmeyi, test türü seçim kararını ve ERP/middleware için senaryo stratejisini öğreneceksiniz.

İçindekiler / Bölüm Haritası

  • Virtual User ve Concurrent User
  • Normal Load, Peak Load, Ramp-up, Ramp-down
  • Load, Stress, Spike, Soak, Capacity Test
  • UI ve API Performans Testi Farkları
  • Mobil Uygulamalarda Backend/API Performans Testi
  • Masaüstü Uygulamalarda Sandbox API Senaryosu
  • Modül Özeti

1) Virtual User ve Gerçek Kullanıcı Kavramı

Virtual User, JMeter içindeki sanal kullanıcıdır. Gerçek kullanıcı ise iş akışında düşünen, bekleyen, farklı adımlara giden kişidir. Bu nedenle virtual user sayısı tek başına yeterli değildir; kullanıcı davranış oranları da modellenmelidir.

Concurrent User, aynı anda aktif işlem yapan kullanıcı sayısıdır. Toplam günlük kullanıcı ile concurrent user farklıdır.

Neden Önemli?
Doğru concurrent model kurmadan yapılan test, canlı trafiği temsil etmez.
Dikkat / Sık Yapılan Hata
"1000 kayıtlı kullanıcı var, testte de 1000 thread açalım" yaklaşımı çoğu zaman gerçek dışıdır.

2) Normal Load, Peak Load, Ramp-up ve Ramp-down

  • Normal Load: Günlük ortalama kullanım düzeyi.
  • Peak Load: Ay sonu, kampanya, vardiya değişimi gibi yoğun zaman.
  • Ramp-up: Kullanıcıların sisteme kademeli giriş süresi.
  • Ramp-down: Yükün kademeli azaltılması.
Örnek model
0-5 dk: 50 kullanıcı
5-10 dk: 150 kullanıcı
10-20 dk: 300 kullanıcı (peak)
20-25 dk: 150 kullanıcı
25-30 dk: 50 kullanıcı
Neden Önemli?
Kademeli yük modeli, sistemin geçiş davranışını ve toparlanma kabiliyetini gösterir.
Dikkat / Sık Yapılan Hata
Tek adımda yüksek yüke çıkmak, gerçek kullanıcı giriş dinamiğini bozarak aşırı stres yaratır.

4) UI ve API Performans Testi Farkları ve Donanım Etkisi

UI testleri tarayıcı rendering, istemci gecikmesi ve ön yüz kaynaklarını da içerir. API testleri backend kapasitesini daha saf ölçer. Donanım planlamasında API sonuçları genellikle daha belirleyicidir.

Karar kuralı: Hangi modül hangi testten geçecek?

  • Yüksek işlem hacmi olan veri servisleri: önce API load/stress.
  • Kullanıcı deneyimi kritik ekranlar: API sonrası hedefli UI doğrulama.
  • Raporlama modülleri: API + DB I/O ağırlıklı senaryo.
Neden Önemli?
Doğru test katmanı seçimi, gereksiz donanım maliyetini ve yanlış darboğaz yorumunu azaltır.
Dikkat / Sık Yapılan Hata
Tüm modülleri aynı test tipiyle sınamak, modülün gerçek riskini maskeleyebilir.

5) Mobil Uygulamalarda Backend/API Performans Testi

Mobil istemci ağ koşulları farklılaşsa da kapasite darboğazı çoğunlukla backend API katmanında oluşur. Bu nedenle mobil performans testi, API tarafında kullanıcı davranışını oranlayarak yapılmalıdır.

  1. Mobilde en çok kullanılan işlem setini belirleyin (listeleme, detay, kaydetme).
  2. Çağrı sıklıklarını yüzdesel modele dönüştürün.
  3. JMeter'da ayrı Thread Group ile mobil trafik desenini üretin.
Neden Önemli?
Mobil kanal yükü düşük görünse bile sık tekrarlanan kısa çağrılar backend'i yorabilir.
Dikkat / Sık Yapılan Hata
Sadece Wi-Fi koşuluna göre test yapmak, gerçek 4.5G gecikme etkilerini gözden kaçırır.

6) Masaüstü Uygulamalarda API Tabanlı Performans Testi (Sandbox Örneği)

Masaüstü uygulamalarda doğrudan UI otomasyonuyla yüksek yük üretmek zor olabilir. Eğer ürünün dışa açık sandbox API katmanı varsa, aynı iş adımları API düzeyinde modellenerek performans testi yapılır.

  1. Geliştirici ekipten sandbox endpoint listesini alın.
  2. İş akışını API çağrı sırasına çevirin.
  3. JMeter'da bu akışı parametreli senaryoya dönüştürün.
Neden Önemli?
API tabanı üzerinden kapasite ölçmek, masaüstü kanalın backend etkisini netleştirir.
Dikkat / Sık Yapılan Hata
Sandbox ile canlı endpoint farklarını dokümante etmeden sonuçları birebir canlı varsaymak.

Modül Özeti

Bu modülde doğru kullanıcı modeli kurmayı, test türünü iş riskine göre seçmeyi ve kanal bazlı strateji geliştirmeyi öğrendiniz.

Bu Modülde Öğrendikleriniz

  • Virtual user, gerçek kullanıcı ve concurrent user ayrımı
  • Normal/peak yük ile ramp-up/ramp-down modelleme
  • Load, stress, spike, soak, capacity test kullanım alanları
  • UI ve API test kararının donanım beklentisine etkisi
  • Mobil ve masaüstü uygulamalarda API bazlı performans yaklaşımı
