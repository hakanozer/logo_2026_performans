Modül 3: Apache JMeter ile Yük Testleri

Bu modülde JMeter ile kod yazmadan test planı oluşturma, API senaryolarını taşıma ve gerçek kullanıcı davranışını modelleme adımlarını öğrenirsiniz.

İçindekiler / Bölüm Haritası

  • JMeter Bileşenleri ve Çalışma Mantığı
  • Basit Test Planı Oluşturma
  • Web ve API Testleri (GET/POST/PUT/DELETE)
  • Postman ile API Hazırlama ve JMeter'a Aktarma
  • CSV Parametrizasyon, Correlation, Session Yönetimi
  • Mobil/Web/API Tek Çatı Yaklaşımı
  • Modül Özeti

1) JMeter Nedir? Bileşenler Ne İşe Yarar?

  • Test Plan: Tüm test kurgusunun ana dosyası.
  • Thread Group: Sanal kullanıcı sayısı, ramp-up, loop ayarları.
  • Sampler: İsteğin kendisi (HTTP Request gibi).
  • Listener: Sonuçların görüntülendiği rapor bileşenleri.
  • Assertion: Beklenen yanıtı doğrulama kuralları.
  • Timer: Kullanıcı bekleme davranışını modelleme.
Neden Önemli?
Bileşen görevlerini doğru ayırmak, senaryonun hem okunabilir hem tekrar kullanılabilir olmasını sağlar.
Dikkat / Sık Yapılan Hata
Thread Group içinde fazla listener çalıştırmak, test üreticinin performansını düşürür.

2) Basit Bir Test Planı Oluşturma (Tıkla → Gör → Yap → Gözlemle)

  1. Sol üstten File → New Test Plan.
  2. Test Plan'a sağ tık: Add → Threads (Users) → Thread Group.
  3. Thread Group alanında: Number of Threads (Users)=100, Ramp-Up=60, Loop Count=5 girin.
  4. Thread Group'a sağ tık: Add → Sampler → HTTP Request.
  5. Server Name, Path, Method bilgilerini doldurun.
  6. Gerekli header için: Add → Config Element → HTTP Header Manager.
  7. Yanıt kontrolü için: Add → Assertions → Response Assertion.
  8. Sonuç için: Add → Listener → Summary Report.
  9. Üstteki Start butonuna basın, sonuçları gözlemleyin.
Neden Önemli?
Bu temel akış tüm ileri seviye senaryoların iskeletidir.
Dikkat / Sık Yapılan Hata
Ramp-up çok kısa verilirse gerçekçi olmayan ani yük oluşur.

3) Web ve API Testleri: Method, Header, Body, Auth, Token

JMeter'da HTTP Request içinde method seçimi yapılır: GET okuma, POST oluşturma, PUT güncelleme, DELETE silme işlemleri için kullanılır.

Authentication için en sık yöntem token taşımaktır. Header Manager içine Authorization alanı eklenir.

Authorization: Bearer eyJhbGciOi...

Response kontrolünde sadece HTTP 200 değil, body içinde iş sonucu alanlarını da doğrulamak gerekir.

Neden Önemli?
Başarılı görünen HTTP kodu, iş sonucu başarısızsa yalancı başarı üretebilir.
Dikkat / Sık Yapılan Hata
Sadece status code assertion koyup uygulama mesajını doğrulamamak.

4) Postman ile API Hazırlama ve JMeter'a Aktarma

  1. Postman açın → New → HTTP Request.
  2. URL ve method girin, Authorization sekmesinden token yapısını doğrulayın.
  3. Send ile yanıtı kontrol edin; doğruysa sağ üstte Code butonuna tıklayın.
  4. cURL formatını seçip metni kopyalayın.
  5. JMeter'da HTTP Request ve Header Manager açıp cURL içeriğini alanlara dağıtın.
  6. View Results Tree ile istek/yanıt detayını kontrol edin.
curl --location 'https://ornek/api/order' \
--header 'Authorization: Bearer TOKEN' \
--header 'Content-Type: application/json' \
--data '{"orderNo":"100045"}'
Neden Önemli?
Postman doğrulaması sayesinde JMeter'a taşınan isteğin fonksiyonel doğruluğu korunur.
Dikkat / Sık Yapılan Hata
Postman'daki otomatik header'ları JMeter'a taşımayı unutmak 401/415 hatasına neden olabilir.

5) JMeter Senaryoları: CSV Data Set, Dinamik Parametre, Correlation

Gerçek kullanıcı gibi davranmak için sabit veri yerine CSV Data Set Config kullanılır. Her sanal kullanıcı farklı müşteri numarası, ürün kodu veya tarih gönderebilir.

  1. Thread Group'a sağ tık → Add → Config Element → CSV Data Set Config.
  2. Filename alanına csv dosya yolunu yazın.
  3. Variable Names alanına sütun adlarını girin (musteriNo, urunKodu).
  4. HTTP Request içinde bu değerleri ${musteriNo} gibi kullanın.

Correlation için bir istekte dönen session id veya token'ı çıkarıp sonraki istekte kullanın.

Regex Extractor örneği
Reference Name: sessionId
Regular Expression: "sessionId":"(.+?)"
Template: $1$
Match No: 1

Assertions ve timer ile gerçek kullanıcı davranışı taklit edilir; düşünme süresi olmayan test gerçekçi olmaz.

Neden Önemli?
Parametrizasyon ve correlation olmadan test, aynı kullanıcıyı tekrar eden yapay bir trafik üretir.
Dikkat / Sık Yapılan Hata
Token yenilenme süresi dikkate alınmadığında uzun testlerde toplu 401 hatası oluşur.

6) Mobil/Web/API Trafiğini JMeter'da Tek Çatı Altında Toplama

Aynı backend'i farklı kanallar farklı şekilde zorlar. Bu yüzden ayrı Thread Group'lar ile karma yük modeli kurulur.

KanalÖrnek İşlemYük OranıNot
WebSorgu + rapor%40Daha uzun response payload
MobilKısa listeleme%35Daha sık ama hafif çağrı
API/EntegrasyonToplu veri aktarımı%25Arka planda sürekli akış
Neden Önemli?
Tek kanal testi yerine karma kanal testi, gerçek canlı davranışına daha yakın sonuç verir.
Dikkat / Sık Yapılan Hata
Sadece mobil trafiği test edip entegrasyon yükünü dışarıda bırakmak, üretimde beklenmeyen darboğaz yaratır.
